Fynd Storefront Scraper

A single-file Node.js CLI tool that scrapes Fynd-platform e-commerce storefronts (e.g. isabydollywahal.com). Given a collection or product URL, it extracts the site's embedded JSON state — no HTML parsing, no LLM — walks pagination to discover every product in a collection, and outputs one CSV with full product details: name, SKU, price, all attributes, and the complete image gallery for each product.

Node.js Built-in fetch Zero npm dependencies Single-file CLI

What the app does

  • URL router

    Takes one URL as a CLI argument. A /product/<slug> URL runs single-product mode; anything else is treated as a collection URL.

  • Embedded JSON extractor

    Reads the site's own server-rendered window.APP_DATA state directly — never scrapes rendered HTML, never uses an LLM. If the JSON block is missing or malformed, that page errors out rather than guessing.

  • Collection pagination crawler

    Walks a collection page by page until the site reports no next page, collecting every product slug along the way. Prints which page it's fetching as it goes.

  • Product detail scraper

    Fetches every product's page and pulls name, SKU, UID, price, brand, description, every attribute, every delivery/customization group, and the full ordered image gallery. Products with unreadable data are skipped and logged, not fatal to the run.

  • Dynamic CSV column builder

    Fixed columns first, then Image 1..N padded to the widest gallery across all scraped products, then every attribute key found across all products, alphabetized. Blank cell when a field is genuinely absent — never a fabricated value.

  • CSV writer

    Writes one CSV file, one row per product, with standard quoting/escaping for values containing commas, quotes, or newlines.

  • Progress logger

    Prints a line per product as it's scraped (name + image count), plus a start summary (products found) and end summary (rows written, output path).

Already provided by the existing codebase

  • A working sequential version of the scraper (scrape.js) already covers URL routing, JSON extraction, pagination, product scraping, and CSV output
  • No package.json, no build step, no framework to configure

Out of scope (v1)

  • Retry/backoff on network failures — a failed fetch just errors out for that product; no automatic retries.
  • Resuming an interrupted scrape — no checkpoint file; re-running starts from scratch.
  • Rate-limiting / configurable delay between requests — no built-in throttling beyond the fixed concurrency of 5.
  • Multi-site config beyond the Fynd platform — targets Fynd's known JSON shape only, not a generic scraper framework.
  • Downloading actual image files — the CSV stores image URLs only, not the images themselves.
  • Proxy / anti-bot evasion — no user-agent rotation, proxy support, or CAPTCHA handling.

Data model

What the app needs to remember while it runs — nothing is persisted between runs.

Product

nameProduct title
SKUThe seller's product code (item_code)
UIDInternal product identifier
priceEffective (selling) price and marked (MRP) price
brandBrand name
descriptionFull description and short description
urlThe product page link
imagesOrdered list of gallery image URLs
attributesOpen-ended key/value pairs — color, fabric, country of origin, category, gender, sizes, etc. — varies per product
grouped attributesLabeled groups (delivery timelines, customization notes), each flattened to one text value

Related to · None — each Product is scraped and written independently; a collection URL is just a list of Product URLs to visit.

Milestones

1

End-to-end scraper

Delivers a fully working, testable CLI: point it at a collection or product URL and get back a complete CSV. Fetching is sequential (one product at a time).

What gets built

  • node scrape.js <url> [output.csv] — accepts a collection or product URL, plus optional output path
  • Detects product vs. collection URLs and routes accordingly
  • Extracts embedded JSON state from any page it visits
  • Walks collection pagination to discover every product slug
  • Scrapes full product details for each slug, one at a time
  • Writes the dynamic CSV (fixed columns, Image 1..N, alphabetized attributes)
  • Logs progress per product plus start/end summaries

Not in this milestone

  • Concurrent/parallel product fetching
  • Any of the out-of-scope items listed above

Done when: running the script against a real collection URL and a real product URL each produce a correct CSV with no fabricated cell values, matching the column rules above.

2

Concurrent fetching

Speeds up large collections by fetching multiple products at once, without changing anything about the output.

What gets built

  • Product scraping runs 5 requests at a time instead of one at a time
  • CSV output, row order not required to match input order, is otherwise identical to milestone 1
  • Progress logging per product still prints as each one completes

Not in this milestone

  • A configurable concurrency flag — fixed at 5
  • Retry/backoff, rate-limiting, or any other out-of-scope item above

Done when: scraping a large collection produces the same correct CSV as milestone 1 but with up to 5 product pages in flight at once, visible in the logs.
